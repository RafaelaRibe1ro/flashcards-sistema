ETAPA 3 — MICROSSERVIÇO DE CATEGORIAS
================================================================================

OBJETIVO
--------
Expandir o sistema de flashcards (monólito Spring Boot + React) com um novo
microsserviço, demonstrando separação de responsabilidades e comunicação
distribuída entre serviços, usando Spring Boot + Spring Cloud (OpenFeign).


ARQUITETURA GERAL
------------------

  [ Frontend React ] (localhost:5173)
        |            \
        | REST        \ REST
        v              v
  [ Monólito ]    [ categoria-service ]
  (localhost:8080)     (localhost:8081)
        |                    |
        v                    v
  [ H2: flashcardsdb ]  [ H2: categoriadb ]

  O monólito (sistema-flashcards) consome o categoria-service via um
  Feign Client (Spring Cloud OpenFeign) para obter o nome da categoria
  associada a cada flashcard. Cada serviço tem seu próprio banco H2 em
  arquivo, independente — não há acesso direto de um serviço ao banco
  do outro.

  São dois projetos Maven independentes (sem POM pai/multi-módulo), cada
  um executado separadamente com `mvnw spring-boot:run` na sua pasta.
  A comunicação entre eles usa uma URL fixa configurada em
  `application.properties` (sem Eureka/service discovery — simplificação
  deliberada, adequada ao escopo do projeto).


CATEGORIA-SERVICE (novo microsserviço)
---------------------------------------

  Porta: 8081
  Banco: H2 em arquivo (./data/categoriadb, relativo à pasta categoria-service/)
  Pacote base: com.rafaelaribeiro.categoria_service

  Modelo de domínio:
    Categoria { id, nome, descricao, criadoEm }

  Endpoints REST (/api/categorias):
    POST   /api/categorias        — cria uma categoria
    GET    /api/categorias        — lista todas as categorias
    GET    /api/categorias/{id}   — busca uma categoria por id (404 se não existir)
    PUT    /api/categorias/{id}   — atualiza nome/descrição
    DELETE /api/categorias/{id}   — remove uma categoria

  Estrutura (mesmo padrão do monólito):
    model/ -> Categoria (entidade JPA)
    repository/ -> CategoriaRepository (Spring Data JPA)
    dto/ -> CategoriaRequestDTO, CategoriaResponseDTO
    service/ -> CategoriaService (interface) + CategoriaServiceImpl
    controller/ -> CategoriaController
    config/ -> WebConfig (CORS) e DataInitializer (dados de exemplo)

  Testes: CategoriaRepositoryTest (@DataJpaTest) e CategoriaServiceTest
  (Mockito), seguindo o mesmo estilo dos testes do monólito.


INTEGRAÇÃO NO MONÓLITO
------------------------

  Dependência adicionada ao pom.xml:
    org.springframework.cloud:spring-cloud-starter-openfeign
    (BOM: org.springframework.cloud:spring-cloud-dependencies:2025.1.2,
    compatível com Spring Boot 4.0.x)

  SistemaFlashcardsApplication.java: anotado com @EnableFeignClients.

  client/CategoriaClient.java — Feign Client declarativo:
    @FeignClient(name = "categoria-service", url = "${categoria.service.url}")
    interface CategoriaClient {
        @GetMapping("/api/categorias/{id}")
        CategoriaDTO buscarPorId(@PathVariable Long id);
    }

  application.properties:
    categoria.service.url=http://localhost:8081

  Mudança no modelo de domínio existente (Flashcard):
    - Novo campo `categoriaId` (Long, nullable) — referência ao id de uma
      Categoria que vive no categoria-service. Não há chave estrangeira
      (FK) no banco, pois a categoria está em outro serviço/banco.

  Enriquecimento na leitura:
    Ao montar o FlashcardResponseDTO, o FlashcardServiceImpl chama
    categoriaClient.buscarPorId(categoriaId) para obter o nome da
    categoria (campo categoriaNome no DTO). Se a chamada falhar (serviço
    fora do ar, id inexistente), o erro é capturado de forma simples e
    categoriaNome retorna null — sem interromper a listagem de flashcards
    e sem handler de exceção elaborado, mantendo a simplicidade do projeto.

  Na escrita (criar/atualizar), o categoriaId enviado pelo cliente é
  apenas armazenado, sem chamada de validação ao categoria-service —
  simplificação deliberada para não exigir tratamento de erro adicional
  no fluxo de escrita.


NOVOS/ALTERADOS ENDPOINTS DO MONÓLITO
----------------------------------------

  FlashcardRequestDTO ganhou o campo categoriaId (opcional).
  FlashcardResponseDTO ganhou os campos categoriaId e categoriaNome.
  Os endpoints existentes (/api/flashcards) não mudaram de assinatura,
  apenas o corpo de request/response.


FRONTEND
--------

  services/categoriaApi.js — chama o categoria-service diretamente em
  http://localhost:8081/api/categorias (listar, criar, excluir).

  components/CategoriaForm.jsx e CategoriaList.jsx — CRUD de categorias,
  acessível pela nova aba "Categorias".

  components/FlashcardForm.jsx — passa a exibir um <select> de categoria
  (opcional), carregado a partir do categoria-service.

  components/FlashcardList.jsx — exibe o nome da categoria como uma
  etiqueta (badge) no card, quando presente, e permite trocar a categoria
  na edição.
