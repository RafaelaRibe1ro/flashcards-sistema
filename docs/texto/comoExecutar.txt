COMO EXECUTAR A APLICAÇÃO
================================

  - Java 21+
  - Node.js 18+
  - Docker (para o RabbitMQ)

PASSO 0 — Subir o RabbitMQ:

  No diretório raiz do projeto (sistema-flashcards/):

    docker compose up -d

  Sobe o broker na porta 5672 e o painel de administração em
  http://localhost:15672 (usuário/senha: guest/guest). É usado pelo
  categoria-service e pelo monólito para trocar eventos (ver
  docs/texto/arquitetura-eventos.txt). Sem ele no ar, os dois serviços
  ainda sobem e funcionam, mas a sincronização de categorias e a gravação
  do histórico de flashcards ficam pendentes até o broker aparecer.

PASSO 1 — Iniciar o microsserviço de Categorias (categoria-service):

  No diretório categoria-service/:

    Windows PowerShell:
      .\mvnw.cmd spring-boot:run

    Linux/Mac:
      ./mvnw spring-boot:run

  Sobe na porta 8081. Recomendado iniciar ANTES do monólito, para que a
  fila de sincronização do monólito já exista quando o categoria-service
  publicar os eventos das categorias de exemplo (`DataInitializer`).

PASSO 2 — Iniciar o Backend (monólito):

  No diretório raiz do projeto (sistema-flashcards/):

    Windows PowerShell:
      .\mvnw.cmd spring-boot:run

    Linux/Mac:
      ./mvnw spring-boot:run

  Sobe na porta 8080.

PASSO 3 — Iniciar o Frontend:

  No diretório frontend/:

    npm install
    npm run dev

PASSO 4 — Usar a Aplicação:

  1. Abra http://localhost:5173 no navegador
  2. Na aba "Categorias": crie categorias (ex: "Java", "Spring Boot")
  3. Na aba "Gerenciar": crie flashcards preenchendo pergunta, resposta e,
     opcionalmente, selecione uma categoria
  4. Na aba "Estudar":
     - O card exibe a pergunta
     - Clique em "Ver Resposta" para revelar a resposta
     - Use "Anterior" e "Próximo" para navegar entre os cards
  5. Para excluir um card ou categoria, use o botão "Excluir" na respectiva lista

  Obs: flashcards e categorias de exemplo são criados automaticamente na
  primeira inicialização de cada backend para facilitar a demonstração.

  Obs 2: se o categoria-service não estiver rodando, o sistema de flashcards
  continua funcionando normalmente — os cards apenas aparecem sem o nome
  da categoria (o monólito lê o nome de um cache local, sincronizado por
  eventos do RabbitMQ, e não faz mais chamada síncrona ao categoria-service;
  ver docs/texto/arquitetura-eventos.txt).

Fluxo sugerido no navegador: aba Categorias → criar uma categoria → aba Gerenciar → criar um flashcard selecionando essa categoria no <select> → confirmar que o card aparece com a etiqueta da categoria.

Se preferir subir do zero (ex: em outra sessão), veja docs/texto/comoExecutar.txt.

Testar o endpoint novo (categoria-service) via curl

# Listar categorias
curl http://localhost:8081/api/categorias

# Criar uma categoria
curl -X POST http://localhost:8081/api/categorias \
  -H "Content-Type: application/json" \
  -d '{"nome":"Docker","descricao":"Containers e orquestracao"}'

# Buscar por id (troque 1 pelo id retornado acima)
curl http://localhost:8081/api/categorias/1

# Atualizar
curl -X PUT http://localhost:8081/api/categorias/1 \
  -H "Content-Type: application/json" \
  -d '{"nome":"Docker e Kubernetes","descricao":"Atualizado"}'

# Excluir
curl -X DELETE http://localhost:8081/api/categorias/1

Testar a sincronização por eventos (categoria-service → RabbitMQ → monólito)

# Com o RabbitMQ e os dois serviços no ar, crie uma categoria
curl -X POST http://localhost:8081/api/categorias \
  -H "Content-Type: application/json" \
  -d '{"nome":"RabbitMQ","descricao":"Broker de mensagens"}'
# Anote o id retornado

# Crie um flashcard associado a essa categoria
curl -X POST http://localhost:8080/api/flashcards \
  -H "Content-Type: application/json" \
  -d '{"pergunta":"O que e um evento?","resposta":"Uma notificacao assincrona de algo que aconteceu.","categoriaId":5}'

A resposta já deve trazer "categoriaNome":"RabbitMQ" — o monólito não fez
nenhuma chamada síncrona; ele leu do cache local (`categoria_cache`),
populado pelo evento que o categoria-service publicou no RabbitMQ.
Acompanhe as filas em tempo real no painel http://localhost:15672
(guest/guest) enquanto executa os comandos acima.

Testar a resiliência (o monólito não depende mais do categoria-service em tempo real):
# Derrube o categoria-service (Ctrl+C no terminal dele) e repita a criação/listagem:
curl http://localhost:8080/api/flashcards
# Os flashcards continuam aparecendo normalmente, com o categoriaNome que já
# estava no cache — sem erro 500 e sem lentidão, porque não há mais chamada
# de rede síncrona nesse caminho.

Testar a fila de trabalho do histórico:
curl http://localhost:8080/api/flashcards/1/historico
# A gravação do histórico agora é assíncrona (fila flashcard.historico.queue);
# no painel do RabbitMQ é possível ver a mensagem sendo publicada e confirmada
# (ack) quase instantaneamente após cada criação/atualização/exclusão de flashcard.

Observação: o shell Git Bash/Windows engasga com acentos dentro de aspas simples no curl -d (dá erro de encoding UTF-8) — nos exemplos acima evitei acentuação por causa disso; no navegador (formulário React) isso não é problema.
